# Web 公開用アセット

`frontend/public/` は、開発と `npm run check` が使う元の実行時素材のままです。ソースアートは `assets/` に残ります。

より小さい公開用画像は次のコマンドで生成します：

```sh
python tools/optimize_web_assets.py
```

生成された `assets/optimized-web/manifest.json` とその `media/` ファイルをコミットしてください。マニフェストには元画像と最適化後の SHA-256 ハッシュ、サイズ、寸法、品質が記録されます。より小さい版に置き換えた画像だけがマニフェストに現れます。

生成器は画像の解像度をそのまま保ち、アトラスには WebP 品質 74、その他の画像には 94 を使い、エンコード方式は 4 です。アルファは 17 段階を使います。完全に透明なピクセルと完全不透明なピクセルは正確なまま、中間の不透明度は最大 8/255 だけ変化します。画像の忠実度はわずかに下がりますが、スプライトのジオメトリは変わりません。

`npm run build` と `npm run build:pages` はこれらのハッシュを検証し、元の public ファイルを Git 管理外の `output/web-public/` にコピーし、選択した画像を置き換え、ネストしたすべての `assets.json` の参照を新しい内容ハッシュ URL に書き換えます。音声、動画、寸法、フレーム座標、元ファイルは保持されます。Vite は本番ビルドでこの準備済みディレクトリを使い、開発ビルドでは元の public ファイルを使います。Vite より先に前処理を走らせるため、npm のビルドコマンドを使ってください。

元のメディアや素材参照を変更した後は、最適化コマンドを再実行してください。置き換えファイルが古いか欠けている場合、その指示とともにビルドは失敗します。また、各フロントエンドビルドは **50,000,000 バイト** を超える `frontend/dist/` を拒否します。スクリプト、スタイル、HTML、すべてのメディアを含みます。既存のシミュレーションとバックエンドのビルド手順は変わりません。
