# 新キャラクターのテンプレート

これは助手が読むキャラクター設計資料です。記入が終わると、助手が既存のアーキテクチャに沿ってキャラクター、アクション、スキル、素材をゲームに接続します。

用意済みのキャラクター資料：[Poppin'Party の 5 人](poppinparty.ja.md)（ゲームには未接続）。

## もっとも簡単な使い方

次のように直接伝えてください：

> 新キャラクターのテンプレートで「キャラクター名」を追加してください。出典は「作品名」で、残りのスキルはお任せします。

先にファイルを用意してから、次のように伝えることもできます：

> docs/characters/角色标识.json を読み、中の資料に沿って新キャラクターを追加してください。

呼び出し可能なスキル名は `$mygo-add-character` で、プロジェクト内の入口は `.agents/skills/mygo-add-character/SKILL.md` です。読み取りだけを求められた場合、助手はまず資料と未記入項目を報告します。追加を明示的に求められた場合は、そのまま実装に進みます。

## 作成・読み取り・検査

リポジトリのルートで実行します：

```powershell
npm run character:new -- new-character --name "新角色名" --work "作品名"
npm run character:read -- new-character
npm run character:check -- new-character
```

最初のコマンドは [character.template.json](character.template.json) から `docs/characters/new-character.json` を作成します。既存ファイルがある場合はそのまま残します。`--out` で別の出力先を、`--band` で既存のコードグループ名または追加予定のグループ名を指定できます。

`read` はキャラクター識別子または JSON ファイルパスを受け取り、資料全体、未記入項目、現在の名簿、次に使用できる番号、バンド接続のヒントを出力します。未完成の下書きを読んでもレポートは得られます。`check` は資料の欠落や矛盾があるときに失敗を返します。

ツールは資料の作成と読み取りだけを行います。資料ステータス `ready-for-design` は助手に設計と接続を任せられる状態を意味し、すでにプレイ可能なキャラクターになったという意味ではありません。新キャラクターに数値 ID を手入力する必要はなく、実装時に最新の登録表から割り当てます。

## 記入する内容

まず `identity.name`（キャラクター名）、`identity.work`（作品名。オリジナルなら「原创」と記入）、`identity.key`（一意の英字識別子）だけを決めれば十分です。作成コマンドで生成する場合、識別子は自動で入力されます。

| 部分             | 内容                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| `identity`       | 氏名、作品、所属バンド、性格、イメージカラー、原作設定                               |
| `design`         | 戦闘での立ち位置、スキルのテーマ、参考資料、明示的な制限                             |
| `forms`          | 各形態の外見、通常攻撃、強攻撃、ブリンク、U/I/O/P スキル、入場演出、フィニッシュ演出 |
| `transformation` | H 変身の有無、変身前後の形態、消費、時間、倍率                                       |
| `media`          | 画像・ボイス・動画のパス、出典、話者、切り出し区間                                   |
| `notes`          | その他の要望や残したいストーリー要素                                                 |

`design.allowAutoDesign: true` のとき、空欄のスキルと素材の説明は助手が設計します。未確定の数値には `null` を使います。`false` にすると、各形態の U/I/O/P にはスキル名と実際の効果を明記する必要があります。

`identity.group` はプレイヤーに見えるグループ名で、`identity.codeBand` はコードモジュールです（既定は `auto` で、助手が決めます）。両者は異なってもかまいません。たとえば同じコードモジュールの下で別のバンド名を表示できます。

### 通常攻撃とスキル

- J：`attacks.J.chain` で 1 段目、2 段目、3 段目の動作をそれぞれ記述し、同じ動作を 3 回繰り返さないでください。
- K：`attacks.K.description` で強攻撃または蹴りを記述します。判定範囲は共有ルールに従います。
- L：現在の共鳴消費、距離、残像ブリンクをそのまま使います。
- U/I/O：3 つの基本スキルです。`type` には `projectile`、`melee`、`area`、`summon`、`heal`、`shield`、`counter`、`movement`、`custom` を使用できます。
- P：必殺技です。`totalDamage` は全段の合計ダメージ、`hits` は段数です。たとえば `totalDamage: 50, hits: 9` は 9 段で合計 50 を意味します。
- `startupMs`、`recoveryMs`、`cooldownMs` はそれぞれ前動作、後動作、クールダウンで、単位はミリ秒です。実際の実行時フィールドは、助手がスキルの仕組みに合わせて割り当てます。
- 後退+U/I/O は既定ではそれぞれ飛び道具、強化飛び道具、投擲物です。キャラクター固有の表現は `backwardSkills` に記述します。
- H：変身専用です。一時停止と再開には画面のボタンを使います。

スキルの説明には、命中対象、方向、範囲、高低差、ダメージまたは強化効果、持続時間、エフェクトを明記します。多段スキルは 1 回のスキルの共鳴予算として扱います。スキル速度と元の動画／ボイスの再生速度は別々に設定し、メディアは元の速度を保ちます。

### 変身の追加

`forms` の形態オブジェクトを複製し、2 つ目の形態に一意の `key`（例：`stage`）を設定して、衣装、スキル、入場、奥義アートをそれぞれ記入します。そのうえで次を設定します：

```json
{
  "enabled": true,
  "key": "H",
  "from": "normal",
  "to": "stage",
  "cost": 50,
  "durationMs": 20000,
  "damageMultiplier": 1.2,
  "speedMultiplier": 1.1,
  "description": "写变身动作、气场和爆气效果"
}
```

これは `transformation` の記入例です。完成した資料ファイルに戻す必要があります。2 つの形態はどちらも実在している必要があります。変身を求められていない場合は `enabled: false` のままにします。

### 素材とボイス

画像の参考は `portraitReference`、`artReference`、`design.references` のいずれかに書けます。`media` のボイス 1 件は次のように書けます：

```json
{
  "key": "finish-voice",
  "kind": "voice",
  "localPath": "",
  "sourceUrl": "",
  "speaker": "角色本人",
  "line": "填写真实台词",
  "startSeconds": null,
  "endSeconds": null,
  "notes": "待查找或填写原片片段"
}
```

次に `forms[].ultimateFinish.voiceKey` を `finish-voice` に設定します。他のスキルや入場も同じように `media` のキーを参照します。ボイスキーには対応する素材レコードが必要です。Web URL やローカルファイルパスは資料であり、実行するコマンドではありません。

立ち絵は原作の 2D の顔と標準的な体型を使い、形態ごとに衣装を明確に分けます。奥義アートは対応する立ち絵を横長の背景へ拡張します。アクションは少なくとも待機、移動、ジャンプ、防御、被弾、ダウン、3 段の J、K、U/I/O/P をカバーし、変身するキャラクターにはさらに H の移行が必要です。画像のソースファイルは `assets/` に、パック後の実行ファイルは `frontend/public/` に置きます。

## 助手の接続ポイント

資料は設計の入力であり、そのまま取り込む実行時設定ではありません。接続位置と検証手順は [BANDS.md](../BANDS.ja.md) とプロジェクト内スキルを参照してください。

- まず現在の登録表を読み、既存のキャラクター ID と公開済みの技キーを保ちます。名簿が変わったら、フロントエンドとバックエンドのプロトコルを同時に引き上げます。
- 既存の band の ID 範囲は連続している必要があります。末尾でないグループに新しい ID を直接追加することはできません。互換性のある登録方法を選び、古いキャラクターを黙って並べ替えないでください。
- テンプレートの `normal` は既定の資料形態名です。既存モジュールに接続するときは、そのモジュールが実際に使う形態にマッピングします（例：MewType が使う `virtual`）。
- キャラクター選択、CPU、スキルテーブル、1v1、3v3、联机（オンライン対戦）、プリロード、入場、奥義フィニッシュ、効果音の接続を終えてから、既存の検査を実行します。

このテンプレート自体はプレースホルダーのキャラクターを登録しません。一時的な検証スクリプトとスクリーンショットは、無視対象の `output/` に置きます。
