# キャラクター表示の鮮明さの改善

2026-10-28：バトルキャンバスが実際の表示サイズと一致せず、全キャラクターがぼやけていた問題を修正しました。元のキャラクター画像、顔立ち、配色、アクション、エフェクトは維持しています。

## 実測の変化

| 表示シーン                           | 旧キャンバスのピクセル | 新キャンバスのピクセル |
| ------------------------------------ | ---------------------- | ---------------------- |
| 1920×1080、画面ピクセル比 1          | 960×540                | 1920×1080              |
| 1440×810、画面ピクセル比 2           | 1920×1080              | 2560×1440              |
| スマホ 390×219.375、画面ピクセル比 3 | 1920×1080              | 1170×658               |

以前は通常の大きな画面でも 960×540 の画面全体をそのまま拡大していました。現在はキャンバスの実際の CSS サイズと画面ピクセル比から描画解像度を計算します。スマホでは必要な分だけ描画し、無駄な巨大バッファを避けます。サイズは ResizeObserver で追跡し、ゲームを離れるときにオブザーバーを解放します。

自動画質調整は維持しています。フレームレートの低下が続くと解像度を下げ、安定すると戻します。バッファの上限は約 2560×1440 で、超高解像度の画面はこの上限に制約されます。キャラクターキャッシュは 64 項目、800 万ピクセルの上限を保ちます。

キャラクターキャッシュの拡大縮小の段階は切り上げに変え、小さくしすぎてから引き伸ばすことを避けます。元画像のピクセル密度に達したときは元のテクスチャをそのまま使います。キャンバスのリセット後は高品質の画像サンプリングを再び有効にし、髪、顔のパーツ、衣服の線を保ちます。

Poppin'Party のオフラインアクションプレビューも表示サイズとピクセル比に合わせて描画しますが、正式なロスターには接続していません。元の PNG とすべての実行時アセットファイルはバイト単位で変更していません。

## 検証

- キャッシュと解像度の検査：キャンバスのピクセル上限、アップサンプリング、元のアンカーとワールドサイズ、キャッシュの再利用、メモリ上限。
- 実ブラウザー：プレイ可能な 16 キャラクター、Mujica の 5 変身、燈のペンギン、愛音のミルクドラゴン、合計 23 種類の表示状態。自動画質の低下／復帰でバトル状態は変わりません。
- 通常の大型画面、高解像度画面、スマホ、Pages のサブパス読み込み。すべてのリソースが正常に読み込まれます。
- Poppin'Party のプレビュー 5 種：通常画面、高解像度画面、スマホ、ウィンドウ調整、アクション切り替えで、キャンバスオブザーバーのエラーはありません。
- `npm run check`、`npm run build`、`npm run build:pages`。

テストスクリプト、鮮明さの比較スクリーンショット、詳細結果は Git 管理外の `output/clarity/` に保存しています。
