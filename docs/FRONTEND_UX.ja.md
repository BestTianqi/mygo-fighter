# フロントエンドの見た目とモバイルプレイ

インターフェースは Ave Mujica に着想を得た月夜の劇場で、チャコールの面、アイボリーの文字、クリムゾンの操作色を使います。コントロールとウィジェットは枠線なしの直角で、色と余白で階層を示し、キーボードフォーカスは常に見えます。ローカルに同梱した Noto Serif SC ファミリーがバナー、見出し、キャラクター名、インターフェース文字を統一します。メインメニューは選択中のバンドの 5 人全員を表示し、既定は Ave Mujica で、MyGO!!!!!、Ave Mujica、夢限大 MewType を切り替えられます。再構成したページ領域、共有コントロール、ランタイム、戦闘カーネルは既存の所有境界を保ちます。

## 10 月 30 日のフロー更新

- バナーは `武道馆当然要比武` で、句読点を付けません。モードボタンは矢印のない簡潔な中央寄せラベルを使います。ヘルプとメインメニューのナビゲーションは、他のコントロールと同じ塗りつぶし Button を使います。続きからは未完了の対戦がある場合だけ表示されます。
- キャラクター選択では現在の禁止/選択の指示と残りのスロットを表示します。立ち絵パネルは隣接する選択領域に合わせて伸びます。中央領域は縦スクロールバーを隠したままスクロールし、ヘッダーと操作フッターは見えたままです。編成カードは正方形で中央寄せの顔を保ち、長い編成はスマートフォンで横にスクロールして現在のスロットに追従します。ステージ選択は、折りたたみ可能なカスタムルールより先に来ます。
- LAN の入口は作成/参加の待機フィードバック、コピー可能なルームコード、接続数を表示します。ホスト操作、ドラフト確定、不足プレイヤー、準備状態には明示的な説明があります。
- 一時停止と最終結果は既存のオーバーレイを使い、再開/再戦/選択/メニューの操作を明示します。オンラインのゲストはホストの再開を待ちます。ルームに戻ることとルームを出ることは別の操作です。2 人または 3 人でもバトル HUD の数値とプレイヤーの識別は読めます。
- 読み込みはキャンセルできます。ランタイムのリクエスト無効化とレンダラー準備の世代管理により、遅れて届いた読み込みが放棄した対戦を開いたり、新しい対戦のアートを削ったりしません。
- ヘルプは基本操作を優先し、詳細は展開式のセクションで示します。ダイアログのヘッダーと閉じる操作は通常のレイアウトに留まり、ルーム設定と重なりません。

今回のビジュアル改訂は 6 種類のビューポートで 69 項目のブラウザーチェックに合格しました。3 つのバンド切り替え、ロスター全員の保持、立ち絵と選択領域の高さの一致、スクロールバーを隠したスクロール、枠線なしの直角コントロール、ローカルの練習/一時停止フロー、モバイルのタップ/長押しとスティック解放を含みます。Pages ビルドも `/mygo-fighter/` で配信し、失敗したリソースやブラウザー例外はありませんでした。証跡は無視対象の `output/playwright/verify-ui.log` と `verify-published-touch.log` にあります。

## 選択とバトルのフロー

10 月 30 日の更新は、デスクトップ、390×844 の縦向き、844×390 の横向きで実際の Edge ブラウザーにより確認しました。無視対象の `output/` にある証跡は次のとおりです：

- `ui-flow/main-report.json`：メインメニューのバンド切り替え、遅延完了を伴う読み込みのキャンセル、アセット取得失敗と成功時の再試行。
- `selection-ux-report.json`：未完成/完成の編成、モバイル 8v8、3 人チーム、練習設定、交互の禁止/選択、ドラフトの再開始。
- `ui-flow-battle/report.json` と `report-final.json`：両方向を含む 12 項目のバトルチェック、実際の戦闘結果、リプレイ/再選択/メニュー操作、短い一時停止メニューでのネイティブタッチスクロール。
- `ui-flow-lan/report.json`：独立したエッジ/ロビー/ルームのサービス経由で 17 項目のチェック。参加失敗、クリップボードのフィードバック、ホスト権限、8v8、禁止、2 人/3 人の実戦、ブラウザーセッションを消去した 5 回の退室リクエストを含みます。

UI 更新は 160 個の手描きタッチアクション素材、すべてのキャラクターアート、戦闘ルール、必殺技ボイス/動画のタイミングを保持します。レンダリング画像のチェックは、キャンセルまたは置き換えされたプリロード世代に加え、破棄とリソース解放も対象にしました。

- ローカルの選択とオンラインのルームには、ビューポートサイズの外枠、スクロール可能な中央領域、常設の操作フッターがあります。ロスターのカードはすべてまとまりを保ち、ステージのサムネイルは横にスクロールします。横向きの低いレイアウトでは、使えるコントロールを減らす前に説明文を減らします。
- 編成スロットはコンパクトな顔の立ち絵と読みやすい名前を表示します。オンラインの禁止と選択は準備と同じ常設フッターを使うため、ドラフトの確定に長いキャラクター説明の下のボタンを探す必要はありません。
- ローカル対戦の開始、メニューからの再開、オンラインプレイヤーの準備完了は、いずれもクリックハンドラー内で非同期読み込みより前に全画面を要求します。ブラウザーはプレイヤーのジェスチャーを必要とします。全画面と横向き固定はベストエフォートで、拒否や未対応の要求でもビューポートを埋めるプレイ可能なバトルは残ります。
- Escape と浮動の終了ボタンで全画面を抜けられます。ネイティブの全画面変化を監視しているため、ブラウザーの操作で抜けた場合もゲームのツールバーが戻ります。メニューは方向固定と全画面を解放します。
- タッチ操作は正方形で文字なしの親指スティックと、正方形の手描きアクションボタンを使います。右下の大きな攻撃ボタンは短いタップで J、300 ms の長押しで K を送ります。直線のプログレスバーと強攻撃のアートが長押し状態を示します。U/I/O は周囲のスロット、P は右側、L は下端のスティックの隣に置きます。変身は固定の任意スロットを保ちます。通常攻撃は 88–110 CSS ピクセル、スキルは 48–60 ピクセル、補助ターゲットは最低 44 ピクセルです。セーフエリアの余白とコンパクトな横向きの低いレイアウトにより、ターゲット同士が重なりません。
- 既存のアクションフレームとフィニッシュアートは、現在のキャラクターと形態に追従します。静止クロップはキャッシュしたソース画像を共有し、立ち絵へのフォールバックを持ちます。アニメーションループは追加しません。斜め入力、移動しながらの攻撃、ポインターのキャンセル、キャプチャの喪失、フォーカス喪失、アンマウントには明示的な解放経路があります。保留中の J/K ジェスチャーも、一時停止、ラウンド、キャラクター、形態の変化でキャンセルします。スティック下部の陰影領域を押し続けると、スワイプなしでしゃがめます。非パッシブのタッチリスナーは、スティック上で始まったタッチだけに対してページのジェスチャーをキャンセルします。目に見えるアクションラベルやスティックの文字がなくても、中国語のアクセシブル名は利用できます。
- ナビゲーションはラベル付きの塗りつぶしボタンを使い、装飾的な矢印は使いません。ゲームのロゴはメインメニューのヘッダーに 1 回だけ表示します。モバイルのバトルには全画面や横向きの案内オーバーレイがありません。全画面と方向の要求は既存のバトルフローを通ります。
- 2 つの体力バーは同じ幅のグリッド列と揃ったセーフエリア余白を使います。全画面のショートカットは HUD の上に別の行として置きます。共鳴ラベルは同じ幅の空間を確保するため、2 本の共鳴レールも同じ長さになります。
- バトルのレイテンシーバッジは隠れたツールバーの外に留まります。オンラインの値は既存の実測ラウンドトリップ時間（RTT）であり、推定の片道遅延ではありません。ローカルプレイ、初回計測、再接続、更新の停滞にはそれぞれ別のラベルがあります。

必殺技による KO では、勝った必殺技の背景がそのセリフを言い終えるまで続きます。待機中のフィニッシュボイスがフィニッシュ動画と 1 秒のアート入場を同時に開始するため、結果表示で必殺技が空白画面に消えたり、アートがフィニッシュ動画より先に抜けたりしません。フィニッシュ動画はセリフ全体を通して残り、次の入場の前に退出します。共有のラウンド終了クロックの最後の 300 ms は演出の完了を待ちます。オンラインのルームでは認証済みの両プレイヤーがその KO tick を確認する必要があるため、音声が遅い側が早く戦い始めることはありません。通常の KO のタイミングとリザーブ入場のエネルギーは変わりません。無音のフィニッシュ背景動画はフィニッシュボイスと同じレビュー済みソース区間を使い、元の速度を保って実際のボイス位置に追従します。一時停止は両方を凍結します。消音時はクリップの長さを使い、動画が使えない場合はイラストを見せたままにします。

## ブラウザーのツールバーの制限

ゲームは対応している場合、`navigationUI: "hide"` で全画面を要求します。ページはブラウザーの UI の除去を保証できません。Web マニフェストは相対の `start_url`、`scope`、アイコンパスと `display: "standalone"` を使い、Apple の Web App メタデータも含みます。対応するモバイルブラウザーでは、**ホーム画面に追加** してそのショートカットを起動すると、ツールバーのないアプリウィンドウになります。インストールしてもオフラインプレイは有効にならず、オンライン対戦には引き続きサーバーが必要です。

iPad の Safari では、ネイティブのパンジェスチャーがページのスクロールとは独立に全画面を解除できます。スティック下部の陰影領域を押し続けると、その下方向のスワイプを始めずにしゃがめます。ブラウザー自身の明示的な全画面終了は引き続き使えます。[WebKit の全画面ジェスチャー報告](https://bugs.webkit.org/show_bug.cgi?id=227387) を参照してください。

参考：[Fullscreen API の要件](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)、[Web マニフェストの表示モード](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/display)。

## 検証

一時的な検証スクリプトとスクリーンショットは無視対象の `output/playwright/` にあります。テストディレクトリや新しいテスト依存は追加しません。ブラウザーチェックは、デスクトップの選択と既定の全画面/Escape、320×568 と 390×844 のスマートフォン、844×390 の横向きと 1024×768 のタブレット、同時のタッチ移動と攻撃、キャンセル、2 つの独立したクライアントによるオンライン 1v1 と 3v3 の禁止/選択ドラフトを対象にします。ブラウザーのエミュレーションは実機の iPhone/iPad のツールバーや方向の挙動を確定するものではなく、それらはインストールされたブラウザーと OS に依存します。
