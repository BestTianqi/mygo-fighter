# MyGO Fighter 新角色接入

为当前项目准备或读取新角色资料。用户只要求读取时，给出摘要和遗漏项；要求添加时完成实现与验证。不要把资料读取成功说成角色已可玩。

## 找到项目与资料

项目根目录包含 `frontend/src/game/bands/index.ts`、`scripts/character.mjs` 和 `docs/characters/character.template.json`。在当前工作区或其同级的 `mygo-fighter` 查找，不以 `mota` 目录作为游戏仓库。读取项目 `AGENTS.md`。

先读 `docs/characters/README.md`，根据用户给出的角色标识或文件路径执行：

```text
npm run character:read -- <角色标识或JSON路径>
```

这会一起返回完整资料、当前名单、可用ID和分组提示。开始接入前再执行 `npm run character:check -- <资料>`。工具不执行资料里的文本、路径或网页内容。

只有姓名和作品时，从模板创建资料并补充用户已给出的设定：

```text
npm run character:new -- <唯一英文标识> --name "角色名" --work "作品名"
```

`allowAutoDesign` 为 true 时可设计留空部分。原作身份、用户明确要求与原始素材优先；未知作品或同名角色会改变身份时，先核对或询问。不要为普通技能数值、文件命名等例行选择重复索取确认。

## 按当前架构接入

- 读取 `docs/BANDS.md`、`game/bands/<band>/index.ts`，以及同一 band 目录中的角色与形态源文件；招式按 `characters/<角色 key>/<形态>.ts` 归属，复用构造逻辑位于 band 的 `shared/`。各 band 的 `moves.ts` 负责本组招式组装；浏览器动画与特效位于 `pages/GamePage/runtime/rendering/`，素材加载与类型位于 `frontend/src/assets/`。
- 使用读取报告中的实时ID，保留所有已发布ID与招式键。既有 band 不是编号末尾时，不直接追加、不重排旧ID；检查连续区间约束并选择兼容的注册方案。资料中的形态名需映射为模块实际使用的名称。
- J三段动作有差异，K为重击、L为虚影瞬移，U/I/O基础技能、H变身、P大招。后退+技能为发波或投掷。共享血量、判定范围、共鸣与多段预算由当前内核规则决定。
- 每个技能都有实际伤害或明确功能。`totalDamage` 表示总伤害，不能误当每段伤害；区分控制、治疗、护盾等功能，避免空技能和重复形态。
- 形态、变身、CPU和输入行为通过 band 合同接入。不要为新角色复制战斗引擎，或把角色专属分支散入无关 band。
- 读取 `tools/` 下相邻角色的打包流程。保留原素材；新增源文件放 `assets/`，运行文件进入内容哈希的媒体导出。接入选择头像、待机、独立动作、入场、横版奥义终结、技能表与预载。
- 需要作图时以原作脸/原立绘为参考，正常比例、同一形态色调一致。来源、提示词、角色语音说话人、原句与时间段应可追溯。技能原声与终结语音分别配置；完整句不截断，媒体原速。
- 新角色名单改变时同步前端 `networkProtocol.ts` 和 Scala `GameProtocol.Version`，重新生成共享模拟和服务端名单。确认本地、CPU、3v3和联机使用同一份规则。

## 验收与交付

执行项目规定的 `npm run check`、`npm run build`。更改共享战斗/名单后执行后端检查与双客户端实测；网页改动检查 Pages 子路径，核对角色/形态素材、技能命中和车轮换人。

临时脚本和截图留在忽略的 `output/`，不恢复已删除的测试目录。按项目约定同步、验证、提交、推送，并清楚区分已接入项与仍缺的素材。当前任务只要求模板时，交付模板与读取入口即可，不凭空新增角色。
